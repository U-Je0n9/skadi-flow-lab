01
노드 = 실행 단위
보통 개발자가 작성한 함수입니다. 상태를 읽고 일을 한 뒤 결과를 돌려줘요. 조건 다이아몬드는 조건부 edge로 구현할 수도 있습니다.
02
LLM = 문장과 의미를 다루는 모델
센서값·알람 순위를 만들어 내지 않아요. 노드가 제공한 구조화 결과와 문서 근거를 바탕으로 설명합니다.
03
MCP = 도구를 부르는 접점
계산·조회·저장 자체는 서버의 서비스 코드가 담당해요. MCP를 사용한다고 모든 도구 선택을 LLM에 맡기는 것은 아닙니다.
이 구분은 논리적 실행 위치입니다. 서버를 몇 대로 나눌지, 모델을 어디에 배포할지, 상태 저장 DB는 무엇인지는 초안에서 확정하지 않았습니다.

ABOUT THIS LAB
설계와 예시의 경계
전체 그래프의 노드 이름·34개 연결·분기 조건은 설계초안 §3을 기준으로 옮겼습니다. 도구 계약은 §5, 실행 흐름은 §6, 응답과 Mock은 §7–§8을 따릅니다.
초안에서 정한 것
한 턴에 기능 하나, 그래프의 분기, MCP 도구 9개, 상태의 역할, 근거 기반 설명, 보고서만 변경 가능한 범위입니다.
이 화면에서 구체화한 것
노드별 JSON 필드 묶음, 실행 추적의 임시 상태 필드 _turn(초안의 필수 필드 아님), 물리적 배치가 아닌 논리적 실행 위치, 가상의 알람·시계열·매뉴얼·저장 응답입니다. 상세 함수 경계와 DB·모델 배포는 구현 시 정합니다.
아직 정하지 않은 것
우선순위 점수식·알람 포함 정책, 추이 계산 기준, 검색 모델·검색 컷오프, 실제 DB 테이블·컬럼입니다. demo-* 버전은 이 학습 화면의 고정 예시입니다.
브라우저 안에서 정해진 데이터를 재생합니다. LangGraph·LLM·MCP·DB에 실제로 연결하거나 보고서를 저장하지 않습니다. 가상 근거와 예시 기준값을 운영 판단에 사용하지 마세요.
